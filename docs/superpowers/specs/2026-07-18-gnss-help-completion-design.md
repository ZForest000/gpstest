# GNSS 调试帮助页补全设计

## 目标

将现有帮助页从 GNSS 术语字典扩展为面向 GNSS 调试用户的应用内诊断手册。用户应能在不离开应用的情况下了解前置条件、各页面用途、常用操作、指标含义，以及 Android、设备和信号环境造成的限制。

## 范围

本次只修改帮助页及其字符串资源，不改变导航、GNSS 数据采集、A-GPS 注入、历史保存或导出实现。帮助内容仅描述当前已存在的界面和行为；对芯片、系统服务、Shizuku/root 和网络来源相关能力，明确标为可选或依赖设备。

## 信息架构

帮助页采用 4 个连续章节，每个章节使用现有 `HelpSection` 卡片样式，保持单页滚动和离线可读。

### 1. 快速诊断

- 使用前条件：授予精确位置权限、打开系统定位服务、在开阔环境等待卫星搜索。
- 无数据排查：依次检查权限、系统定位、环境遮挡与设备 GNSS 支持情况。
- 定位解读边界：首次定位和精度受星历、时间、可见卫星、遮挡、多路径与设备实现影响。

### 2. 页面与操作指南

- 总览：概览定位状态、TTFF、PDOP、星座健康和信号比较。
- 卫星列表：解释“定位中 / 可见 / 搜索中”分组、筛选、排序、冻结显示和点按详情。
- 天空图：说明天顶/地平线映射、点的视觉编码、星座筛选、点按详情、拖拽缩放、双击复位和北向上模式。
- 定位与精度：说明位置、TTFF 重置、DOP 趋势和本地解算仅在原始观测及星历足够时显示。
- 接收机诊断：说明时钟、能力、天线信息、RINEX 导出的前提条件。
- 历史：说明手动保存、自动快照、筛选、CSV 导出和清理的影响。
- NMEA 与导航电文：说明 NMEA 开关位置、冻结、清空、筛选和分享；导航电文为空可能由硬件或信号条件导致。
- 设置：说明主题、NMEA 输出和历史快照策略。

### 3. 指标与原始数据参考

保留当前 TTFF、位置、星座、DOP、卫星信号、时钟、A-GPS 和原始测量章节。补充说明：DOP/CN0 阈值是经验参考；Android 位置精度是估计半径，不是实际误差保证。

### 4. A-GPS 与高级能力

- A-GPS：解释下载、导入、校验、注入、同步时间、自动更新和清除辅助数据的作用与风险。
- 限制：注入成功不表示立即定位；自定义下载地址应来自可信来源；设备可拒绝或忽略部分辅助数据命令。
- Shizuku/root：说明仅用于扩展诊断数据，未安装或未授权不会阻断常规 GNSS 监控；ADB 模式与 root 模式的权限不同。

## 资源与实现边界

- `HelpScreen.kt` 只负责按章节组织 `HelpSection`、`HelpText` 和 `HelpSubItem`，不引入状态、网络或导航逻辑。
- 中英文文本均进入对应 `strings.xml`，不在 Kotlin 中硬编码新的用户可见文本。
- 新章节使用 Material 图标表达主题；不会新增自定义图形或交互控件。
- 将现有帮助卡片圆角从 12 dp 调整为项目 UI 规范要求的最大 8 dp。

## 质量与验证

- 为帮助内容的章节定义提取为纯 Kotlin 数据或常量，以便 JUnit 验证所有要求章节都存在，且中英文资源键完整。
- 先运行新增测试确认其因缺少章节而失败，再添加最小定义与界面渲染。
- 运行 `./gradlew testDebugUnitTest`、`./gradlew ktlintCheck` 和 `./gradlew assembleDebug` 验证单元测试、格式和 Android 编译。

## 非目标

- 不实现页面内上下文帮助、搜索、远程文档链接或帮助分析。
- 不为不受应用控制的 Android 系统定位开关、GNSS 芯片能力或 Shizuku 授权提供自动修复。
